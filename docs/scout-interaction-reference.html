Scout 前端交互参考

对标通用 AI 对话桌面应用（WorkBuddy 这类产品）的交互范式，拆成可落地的规则清单，用于指导 Scout scout/web/static/index.html 的对话/过程区/输入区改造。本文只给规范，不改代码； 末尾附「现状对照 + 优先级清单」，并标注改造中顺手发现的两处选择器失效。

1消息流（核心）

用户感知最强的部分。目标是：流式自然、气泡边界清晰、每条消息可操作、长对话可回看。

流式输出

逐 token 渲染，新内容自动贴底； 用户一旦向上滚动就停止自动贴底，出现「↓ 回到底部」悬浮按钮。光标用一个会呼吸的 ▍ 表示"仍在生成"，结束时消失。

气泡边界

同一回合的所有过程 + 正文收进同一个气泡； 回合结束才 finalize 并开启新气泡。避免一次回答被切成 N 段、头像反复出现（Scout 已用 AgentBubble 做到）。

消息操作条

hover 时浮出：复制 / 重新生成 /（可选）反馈。 操作条不占常态空间，避免干扰阅读。复制成功给轻提示（toast 或按钮瞬变 ✓）。

元信息行

头像 + 角色名 + 时间 + 状态徽章（执行中/完成/错误）+ 步骤计数， 一行排开。状态徽章用语义色：执行中=琥珀、完成=绿、错误=红、压缩=蓝。

关键原则：过程区与正文区分离。过程（思考/工具）在气泡顶部、可折叠、完成后整体弱化（降透明度 + 折叠成一行摘要）；正文始终清晰突出。这正是上一轮已做的「Codex 式收尾」，保持即可。

2思考与过程区

承接上一轮"全面收敛"的改造。规范如下，改造时别再退回三套标签。

层触发条件呈现默认态
短思考 / 工具前叙述< 500 字累积进同一行「思考记录 ×N」折叠
深度思考段≥ 500 字独立「深度思考 · 第 N 段 · X.Xk 字」折叠，展开限高 280px 滚动
收尾摘要回合完成过程区整体折叠成「已完成 N 步 · N 次工具调用 · Xs」折叠

  • 计数（×N、段数、字数）要始终显示，空内容绝不建行（上一轮已修）。
  • 长段展开后必须限高 + 内部滚动，避免英文推理原文铺满一屏。

3工具调用卡片

工具执行是 AI 应用的高频交互，卡片要做到"可扫读、可展开、状态清晰"。

  • 行结构：图标 + 工具名 + 调用计数 + 状态（执行中=spinner 贴右，完成=✓ 贴右），箭头再贴右。
  • 同名工具合并成一张卡（显示 ×N），用 call_id 精确归属输出，防止并行串卡（Scout 已做）。
  • 默认只显示一行摘要；点开看入参（折叠 JSON）+ 输出，长输出限高滚动。
  • 执行中的行：工具名用强调色，spinner 用 margin-left:auto 贴右——不要再给箭头也设 auto（上一轮居中 bug 的根因）。

4输入区（Composer）

输入框是"停留时间最长"的组件，细节决定顺滑感。

发送/停止

输入时=发送；生成中自动切换成停止（方块图标）。 一个位置一个主操作，别并排放两个。

快捷键

Enter 发送、Shift+Enter 换行； 生成中 Esc 停止。按钮 title 里要写明。

辅助工具行

附件 / 语音 / 模式选择（快速·思考）/ 模型选择， 统一用小图标按钮 + hover 提示；模型选择给跨厂商菜单。

自动增高

textarea 随内容增高（设 max-height）， 不要中途出现内部滚动条；附件以缩略 chips 显示、可删除。

5滚动与定位

  • 判断"贴底"阈值用 距离底部 < 100px（Scout 已是 100）；满足才自动滚，否则浮出回底按钮。
  • 历史会话加载时直接定位到底部（用户最想看最新），而不是顶部。
  • 切换会话 / 回到"正在回复的会话"时，重新绑定到最后一个 agent 气泡并贴底（Scout 的 rebindLast 已做）。
  • 长消息内的代码块、深度思考段各自内部滚动，不带动外层消息流。

6状态与反馈

确认对话框

危险/不可逆操作用居中模态（遮罩 + 取消/确认）， 别用浏览器原生 confirm()。确认按钮用危险色。

轻提示 Toast

复制成功、保存成功、非致命错误用右上角 toast， 自动消失（3s），带语义色图标。不打断输入。

错误呈现

请求失败在气泡内显示可重试的错误行 （重试按钮），而不是只弹一个全局 alert。

加载态

首帧/重连用骨架或呼吸占位，避免空白闪烁； 生成中状态徽章常驻元信息行。

Scout 现状：渠道停止等仍用原生 confirm()/alert()（如 index.html:1341/1350）。 已有 showConfirmDialog()（模态）但对话外的管理操作还在用原生弹窗——风格不统一，建议统一到模态。

7动效节奏

统一的时长与缓动 token，避免每个交互各设各的速度。建议：

快交互 120–150ms 展开/折叠 180–220ms 模态进出 200–260ms ease-out（进入） ease-in（离开）
  • 只动 transform / opacity，别动 width/height/top（掉帧 + 抖动）。
  • 流式打字用 CSS 呼吸光标，不用 JS 逐字 setTimeout（省 CPU）。
  • 尊重 prefers-reduced-motion：开启时把动效时长降到 0。

8主题与无障碍

  • 全站走 CSS 变量 token（--c-surface-* / --c-ink-* / --c-line / --c-accent）， 深/浅色各一套；禁止在 HTML 里写死 hex（上一轮已收敛，保持）。
  • 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1；语义色不只靠颜色，配图标/文字。
  • 可点元素有 :focus-visible 焦点环；折叠/卡片可键盘展开。
  • 所有按钮/图标按钮有 title 或 aria-label。
