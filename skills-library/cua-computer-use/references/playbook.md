# CUA 细节配方（playbook）

> 本文件由主 SKILL.md（v2.1.0，2026-09-29）拆分而来，内容与 v2.0.0 全量一致。
> 按需读取：遇到陌生应用、异常界面或连续失败 2 次时再读，平时不要加载。

## 防点错三件套（工具已内置）
- **probe 先行**（读操作无副作用）：点前 `probe x= y=` 或 `probe rel_x= rel_y=`，返回命中控件或"无命中（空白/自绘）"——命中空白 = 千万别点，按截图改 rel 再 probe。probe 顺带返回判档标签。
- **snap 自动吸附**（click 家族默认开）：自动吸附命中控件中心，回复含 `吸附→Button "发送"`。
- **命中回读**：点完看 `吸附→` 与 `focus=`；无吸附行且界面没变 = 点空了，别重复点。

## 优先级总原则：L0 > L1 > L2 > L3（能走结构接口就不碰像素）
- **L0 结构接口**：应用自带 CLI / COM / URL Scheme / 浏览器 CDP（Office 走 COM、浏览器走 browser 工具、支持 deep-link 的应用直接 launch URL）——最稳最省
- **L1 UIA/win32 控件树**：click_control/type_control 按名操作（T1/T2）
- **L2 窗口相对坐标**：rel_x/rel_y + snap（T3）
- **L3 像素/视觉**：find= VL 定位（兜底，自带 UIA→OCR 降级链）
写操作带 verify_screenshot=true 会返回四态验证（confirmed/partial/suspected_noop/unverifiable），
suspected_noop 时回去重新观察，不要盲目重试。

## 判档（陌生应用第一步 probe 任意点）
| 档位 | probe 表现 | 是什么 | 策略 |
|---|---|---|---|
| **T1-UIA** | `[T1-UIA] 命中: Button/Edit...` | 现代 Win32/WPF/UWP/Electron | click_control/type_control 最稳；rel+snap 可用 |
| **T2-Win32** | UIA 空、`[T2-Win32] 命中` | Delphi/MFC/VB6 老软件 | 工具自动兜底 win32 树：按名操作/snap 均可用 |
| **T3-自绘** | 两树均无命中 | 微信 4.x/腾讯会议/钉钉/游戏 | 截图→rel→snap=false 精确点→验证→macro 固化 |
判档别凭印象：微信 4.x 是 T3、飞书是 T1；老行业软件多是 T2 而非 T3。probe 报"点不在窗口矩形内"= 坐标系错位，改 rel。

## 恢复策略表（失败时禁止原样重试同一动作）
| 症状 | 判定 | 对策 |
|---|---|---|
| 截图与上一步几乎一样 | 点空/未生效 | 换路径：find 换更具体描述 / probe 看落点 / 换 rel |
| 出现计划外弹窗/对话框 | 被打断 | 先读弹窗→确认/取消/输入→处理完再回主线；**绝不无视弹窗继续点**（点击会落在被遮挡目标上） |
| 界面在加载/转圈 | 未就绪 | `wait seconds=2` 再截图（截图自带屏幕 diff 短路，等得起） |
| 目标控件找不到 | 路径不通 | scroll 滚动找 / 回上级菜单重新导航 / 换搜索入口 |
| 窗口找不到 | 进程名不对/托盘化 | process= 而非 title；launch/activate 自动恢复托盘 |
| 连续 2 次同动作无效 | 死循环 | 停下换策略或如实报告卡点，**绝不第三次原样重复** |

## 分段控件（日期/时间选择器）打法（2026-09-10 腾讯会议实测教训）
QDateEdit/DateTimePicker 等**分段控件**是 T3 自绘应用的硬骨头：
- **禁止整串输入/粘贴**："2026/9/11" 会被逐字符解析到各段，实测日期被篡改成 2/2、4/2
- 首选 **`set_date date=2026-09-11`**（专用原语：自动定位 QDateEdit/DateTimePicker 控件，年→月→日逐段键入）
- 手动姿势：click 聚焦到年段 → 键入 4 位数字（Qt 自动跳下一段）→ 依次月、日；或逐段选中后覆盖
- 键盘方案失败 2 次即停：分段控件不是"再试一次"能解决的，立刻走下条规则

## 客户端 → 网页版降级（防死磕到熔断）
主流应用都有网页版（meeting.tencent.com、docs.qq.com、mail.qq.com…），网页是标准
HTML 控件，browser 工具 fill/click 稳定 10 倍。**客户端自绘控件连续 2 次操作无效
→ 立即评估网页版路径，不要在客户端死磕**——GUI 任务每步带截图，token 消耗极大，
死磕的终点是熔断（250k 新输入 token）而非成功。

## 误触不可逆按钮后的主动清理
可能误触了"预定/发送/提交"类按钮时：**不要把善后丢给用户**——主动进入列表页
（已预定/已发送/历史）核实是否存在误操作产物，能删则删，再如实报告"确认无残留"
或"发现并已删除"。安全红线的完整语义是"防误操作 + 误了要收拾"。
