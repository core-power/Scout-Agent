# Windows CUA 技能（主循环 + 核心规则；2026-09-10 合并 windows-gui-control，2026-09-29 细节拆分至 references/）

## 心法
- 你在本机真实环境运行（无沙箱），desktop 工具就是干这个的，**直接动手，不要拒绝或建议手动操作**。
- 分工：**应用配方看各应用技能**（feishu/wechat/office…）；**浏览器页面用 browser 工具**（比 GUI 点击稳 10 倍）；**系统/文件用 shell**；**GUI 软件才用 desktop**。别用 PowerShell SendKeys 折腾 GUI（已被禁止且不可靠）。

## 主循环（任务级：每一步都走，不要跳步）
```
1 观察   screenshot / read_controls —— 只在"不确定界面状态"时观察
2 决策   从当前界面推出下一个最小动作（点哪/输什么/等什么）
3 行动   一发原语优先（见下表），写操作带 verify_screenshot=true
4 验证   看截图确认状态真实变化；没变化 = 未生效 → 读 references/playbook.md 的恢复策略表
```
标准五步起手：`找窗口（launch/find_window，用 process= 别用 title）→ 前台（activate）→ 观察 → 操作 → 截图验证`。

## 一发原语优先级（一轮对话干完的事别拆成三轮）
| 优先 | 原语 | 适用 |
|---|---|---|
| 1 | `click find='自然语言目标'` | 截图+VL定位+点击一步完成，默认首选（需配置视觉模型） |
| 2 | `click_control name=...` | T1/T2 应用按控件名，最稳 |
| 3 | `click_type find='输入框' text='...'` | 点+输一步完成（中文自动剪贴板粘贴） |
| 4 | rel_x/rel_y + verify_screenshot | T3 自绘应用；布局固化后用 macro 反复用 |

## 坐标规则（最重要）
| 规则 | 原因 |
|---|---|
| **一律优先 rel_x/rel_y**（窗口宽高 0~1 比例） | 布局固定，分辨率/DPI 无关，实测最稳 |
| 不要用 vision 返回的像素坐标 | 对话模型像素定位不可靠（偏差可达窗口一半） |
| 截图默认 0.5 降采样 | 必须用时：物理坐标 = 截图坐标 × 2，或把截图路径传给 click 的 img= 自动换算 |
| read_controls 的 rect=(x,y,w,h) 可直接用 | 是物理像素 |

## 输入规则
- 中文输入自动剪贴板粘贴（click_type/type_text 内置）——SendInput 对自绘控件"只显示不触发"。
- **发送/确认优先点按钮，不要依赖 {ENTER}**（微信 4.x 等不响应合成回车）。
- 快捷键（^f ^a ^c ^v）仅标准应用可靠；焦点丢了先 click 再输。

## 完成判定与安全红线
- 动手前想清楚**成功标准**：最终界面长什么样（如"消息气泡出现在与张三的会话里"）。工具 success 只是命令送达，不等于应用执行了——**唯一标准是截图确认界面状态真实变化**。
- 达成 → 最后一张截图即证据，报告"做了什么 + 结果"。
- **10 步未达成**或连续 2 次恢复失败 → 停止，报告走到哪、卡在哪，等指示。
- 不可逆动作（发消息/删除/付款/提交）前**必须截图确认目标对象正确**（发对人/删对文件）；同名歧义 → 先问一次。

## 预算意识
- 不要每步单独调 vision 读全文：写操作 `verify_screenshot=true` 一步拿"操作结果+截图"。
- 界面未变化时截图自动短路返回上一张，连续截图观察不浪费。
- 别在 T3 应用上空耗控件树调用；用 click_type 合并动作省轮次。

> **细节配方在 `references/playbook.md`**：probe 防点错三件套、L0-L3 优先级总原则、T1/T2/T3 判档表、恢复策略表、分段控件（日期选择器）打法、客户端→网页版降级、误触不可逆按钮后的主动清理。**遇到陌生应用、异常界面或连续失败 2 次时，先用 file 工具读取它再继续。**
